## What's open (next session)

### Highest-leverage: #290 — implement `forward_decode_pipelined_hybrid`

The user's insight: at PP=2 each step keeps stage_0 GPUs idle while
stage_1 runs, and vice versa — ~50 % of GPU time wasted. Pipelining
slot k stage_1 with slot k+1 stage_0 unlocks **1.6× at PP=2/N=4 / 2.9×
at PP=4/N=8**, orthogonal to all kernel work. This is the next
priority and the cleanest path to the 3× cert gate.

**Read first**: `doc/V1.x/pipelined_decode.md` — the design with
speedup table, event pattern, scratch-reuse argument, and #275-style
pitfalls.

**Reference template**: V2.25.h 1F1B prefill in
`crates/models/qwen3-moe/src/forward/pp.rs` lines 1480-1700 — the
exact `HipEvent::new + peer_copy_via_host_async(bridge_event=...)`
pattern, just for prefill. Decode mirrors this with one event per slot
per inter-stage hand-off (sized to `max_tokens` in
`RankForwardPrefillScratchTp.pipeline_bridge_events`, plumbing
already in `tp.rs`).

**The gotchas to remember (we already burned cycles on these)**:
1. `peer_copy_via_host_async` takes `src_stream` + `dst_stream` args.
   The streams MUST be from the **sub_cluster**, not the global_cluster
   (#275 root cause). Pass `stage_0_sub.device(0).default_stream()` and
   `stage_1_sub.device(dst_local).default_stream()`.
2. `bridge_event` is created with the SOURCE device's id
   (`HipEvent::new(stage_0_sub.device(0).id())`), but `stream_wait` is
   called on the DESTINATION's stream — HIP allows cross-device wait
   on a single event handle.
3. Same-source bounce buffer is one-per-rank per default lane. Slot
   k+1's DtoH on stage_0_stream runs after slot k's DtoH (same stream
   = sequential). Bounce reuse safe at ubatch=1.
4. The N=1 case must be **bit-identical** to the existing batched
   driver with `slots=&[single]` — that's the regression guard the
   scheduler can use to A/B safely.

## Diagnostic toggles to remember

- `FLAMBEAU_BATCHED_DECODE=1` — engages the batched path (default off).
- `FLAMBEAU_INFLIGHT_SLOTS=N` — slot pool size, default 1.
- `FLAMBEAU_BATCH_WINDOW_US=1500` — leader's coalescing wait, default
  1500 µs.
- `FLAMBEAU_FORCE_BATCH_WINDOW=1` — leader sleeps even with no other
  active slot (forces N=2 join in stress tests).
- `FLAMBEAU_NO_FAST_PATH=1` — disables the single-user shortcut so
  every dispatch goes through `forward_decode_batched_*` (debug only,
  slows N=1).
- `FLAMBEAU_GDN_NO_BATCHED=1` — falls back to per-slot
  `forward_gdn_decode_tp` loop instead of batched-GDN (A/B for
  regression bisects).
- `FLAMBEAU_TRACE_BATCH=1` — emits `[TRACE-BATCH t=...ms slot=N pos=...]`
  events at every PUSH/LEADER/DRAIN/DISPATCH/WAIT in
  `routes.rs::decode_via_scheduler_into`. Diagnostic gate for any
  scheduler-race investigation.
