# P2.9b-i2-F throughput cert RE-RUN — post-#266c batched-attention wired

**Date**: 2026-05-04
**Model**: Qwen3.6-27B-Q4_1 (qwen35moe arch, hybrid GDN + full-attn + dense FFN)
**Topology**: pp2tp2 — `--devices hip:0,2,1,3 --pp-size 2 --tp-size 2`
**Build**: post-#266c kernel wired into both `forward_full_attn_layer_decode_batched`
(PP) and `forward_full_attn_layer_decode_batched_tp` (TP).

## Result: 1.02× end-to-end — gate still blocked, bottleneck shifted to GDN

| metric                          | this run     | prior (#267) |
|---------------------------------|-------------:|-------------:|
| 4 sequential 128-tok            | **20.95 s**  | 20.95 s      |
| 4 concurrent 128-tok (N=4)      | **20.49 s**  | 21.34 s      |
| speedup vs sequential           | **1.02×**    | 0.98×        |
| target gate                     | ≥ 3.0×       | ≥ 3.0×       |

Output across 4 concurrent: bit-identical (md5 match), coherent.
Single-user N=1 path unchanged (no regression).

## Why end-to-end didn't shift, when the kernel wins 4-8× in microbench

The #266b microbench measured **attention only** at the Qwen3.6-27B
TP=2-local shape (n_q=16, n_kv=2, hd=128, kv_len=1024). Per-launch:

| N | serial | batched | speedup |
|---|-------:|--------:|--------:|
| 1 |  846 µs |  848 µs | 1.00×   |
| 2 | 1698 µs |  853 µs | 1.99×   |
| 4 | 4577 µs | 1137 µs | 4.03×   |
| 8 |10815 µs | 1331 µs | 8.12×   |

So the kernel itself does what the design promised. But Qwen3.6-27B's
hybrid layout is **3 GDN layers per 1 full-attn layer**
(`full_attention_interval = 4`, see `crates/models/qwen3-moe/src/config.rs`).
With 64 layers total: ~16 full-attn + ~48 GDN.

Per-token wall on hybrid decomposes (rough):

```
T_per_token ≈ T_full_attn * n_full + T_gdn * n_gdn + T_other
            ≈ T_attn * 16     + T_gdn * 48     + T_proj+ar+...
```

Concurrent at N=4:
- `T_attn` is now ~1.0× (was 4×) thanks to #266c. Saves
  ~`(4-1)/4 * T_attn * 16 = 12 attn-units`.
- `T_gdn` still scales 4× linearly (per-slot loop). Costs
  `(4-1) * T_gdn * 48 = 144 gdn-units` extra over 1 sequential.
- Other batched ops (Q/K/V proj, FFN, AR, output head) already
  scaled in #267's run.

Net: GDN dominates (3× the count of full-attn) and is still
linear-in-N, so the hybrid-throughput-on-hybrid 3× gate is not
reachable by lifting attention alone.

## What's now certified ready

- **Correctness across the wired path**: Qwen3.6-27B / pp2tp2 / N=2
  produces output bit-identical-within-batch and coherent. N=1 is
  bit-identical to legacy single-slot. N=4 (this cert): all 4 outputs
  identical and coherent.
- **The kernel itself**: bit-identical parity sweep across 11 shape
  combinations, no spills, scales 4-8× at the perf microbench shape
  (cert: `certs/gfx906/attention_decode_f16_batched.json`).
- **Two wirings**: PP variant (`forward_full_attn_layer_decode_batched`)
  and TP variant (`forward_full_attn_layer_decode_batched_tp`) both use
  the new kernel; `FullAttnPrefillScratch` carries the new per-slot
  pointer/length tables.

## Path to ≥ 3.0× on hybrid

The remaining lever is **batched GDN** — an analogous transformation for
the 75 % of layers that this kernel doesn't touch. Specifically, fuse
the per-slot loop in:

- `forward_full_attn_layer_decode_batched_*` GDN branch (call sites in
  `forward/hybrid.rs` per-rank loop).

Estimated win after batched-GDN lands: GDN's 48× cost shifts from
linear-in-N to roughly the per-block scaling we saw for attention
(1× → 1× through N=4 in the microbench). End-to-end speedup at N=4
should approach 3-4× — same arithmetic as the #266 design analysis,
applied to the GDN side.

Likely additional levers visible at that point:
- AR-residual call overhead at N=4 — currently not the bottleneck but
  may surface once GDN+attn are batched.
- Output head per-slot loop — same pattern; ~1 % wall today, may
  surface at high N.

## On non-hybrid models

For pure-attention dense models (e.g. Qwen3.5-9B), the kernel should
give a substantial direct win because there is no GDN cost to dominate.
A separate throughput cert on dense will quantify that and is queued
informally.

## Reproduce

```bash
FLAMBEAU_BATCHED_DECODE=1 FLAMBEAU_INFLIGHT_SLOTS=4 \
  ./target/release/flambeau serve \
  --model /artefact/models/Qwen3.6-27B-Q4_1.gguf \
  --devices hip:0,2,1,3 --mesh-mode pp+tp --pp-size 2 --tp-size 2 \
  --port 8080
```

Then 4 concurrent vs 4 sequential `/v1/chat/completions` with
`temperature=0`, `max_tokens=128`. Wall difference is the residual
GDN-per-slot ceiling; correctness is bit-identical-within-batch (#275
+ #276 fixes both validated).
