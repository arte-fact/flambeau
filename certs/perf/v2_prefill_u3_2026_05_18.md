# v2 prefill after U3 (n_tokens-aware composites, 2026-05-18)

## Setup
- Model: `/artefact/models/Qwen3.5-9B-Q4_1.gguf` (hybrid: GDN + dense-attn alternating, dense FFN)
- Topology: SingleDevice on hip:0 (gfx906 MI50)
- Prompt: 256× "the quick brown fox " + " Reply: ok" → 1044 prompt_tokens
- `max_tokens=1`, `--prefill-ubatch 512`, `--ctx-cap 4096`
- 3 runs after 1 warmup

## Results

| Path                         | wall (s) | prefill_tok/s |
|------------------------------|---------:|--------------:|
| legacy (FLAMBEAU_V2=0)       |    2.07  |    503        |
| v2-pre-U3 (single-token loop)|   25.7   |     40.5      |
| v2-post-U3 (batched MMQ)     |    8.16  |    128        |

**3.16× speedup over the v1 v2-stack baseline. Gap to legacy: 3.9×.**

## What U3 changed

- `ForwardCtx` trait widened: every composite method takes `n_tokens`
  (or `&[u32]` for `embed`). One method per op for decode (N=1) and
  prefill (N>1).
- `core/composites/*.rs` batch natively where the leaf kernel takes
  a batch dim (`rmsnorm`, `qmatmul` with `m=N`, `kv_append`, RoPE,
  attention prefill kernel, dense FFN). N=1 keeps the fused
  `rmsnorm_quant_q8_1` path; N>1 unfuses to produce both standard
  Q8_1 and MMQ-layout Q8_1 activations.
- ScratchPool grows `norm_q8_1_mmq` / `attn_out_q8_1_mmq` /
  `gated_q8_1_mmq` slots, allocated only when `prefill_ubatch > 1`.
- Per-token scratch slots (resid/norm/q/k/v/gate/attn_out/gate_f32/
  up_f32/gated/down/router/moe_accum/position) sized at
  `max_prefill_tokens * <per-token width>`.
- `moe_ffn` and `gdn_layer` loop internally at N>1 (the state-step
  is sequentially dependent — qmatmul-batching here is a perf
  follow-up).

## Remaining gap (3.9× to legacy)

Qwen3.5-9B is a **hybrid** arch: 32 layers alternating GDN ≈ 16 and
FullAttn ≈ 16 (with a fixed pattern). GDN layers go through the
per-token loop in U3's first cut. Estimated wins still on the table:

- **Batched GDN forward (~2× expected)**: project all N tokens'
  Q/K/V/gate in one matmul each (already batchable at the leaf),
  loop only the recurrent state-step. Legacy does this.
- **Batched MoE forward (~1.5× expected on qwen3.6 MoE)**: permute
  tokens by routed-expert, run each expert as a batched matmul over
  its assigned tokens, scatter results. Loop fallback today.
- **Batched embed** — N memcpys → one strided gather kernel.
  Minor (~1% of forward time).
- **Output head emits last-token-only** — already done, no work
  remaining.

Combined: batched GDN + batched MoE would close ~60-70% of the
remaining gap. Estimate post-perf-follow-up: ~300-400 tok/s, vs
legacy 503. A dense arch (gemma4-v2) should match legacy more
closely today because there's no GDN/MoE to fall back to a loop.

## Architecture validated

- Decode path unchanged: v2 matrix 13/13 PASS (qwen35-9B/27B,
  qwen36-27B/35B-A3B across SD/TP/PP/pp2tp2 on Q3/Q4/Q4_K_XL/Q8_0).
- N=1 composite path identical to pre-U3 (fused rmsnorm_quant_q8_1,
  attn_decode kernel, MMVQ qmatmul dispatch).
- N>1 path active end-to-end on long-prompt prefill, correct logits
  (greedy output "ok" matches the prompt's instruction).
