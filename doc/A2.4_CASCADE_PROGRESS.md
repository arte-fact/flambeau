# A2.4 engine-genericization cascade — progress tracker

Goal: remove `HipDevice` / `HipStream` / `OpsRegistry` / `HipOps` from the
`flambeau-forward` engine so it threads one `<B: Backend>` parameter (the A1
bundle) — the last decoupling step before a CUDA backend can plug in. HIP stays
the sole impl throughout; type-only changes, no behavior change.

Branch: `feature/cuda-decouple`. Net so far: AR seam (C1–C3) + cascade
layers 1–2 are landed; layer 3 (the atomic core) remains.

## Technique

Bottom-up. **Widening** a callee from `&HipDevice` to `&impl Device` is
backward-compatible — existing callers passing `&HipDevice` coerce — so each
mechanical layer compiles green on its own and is committable. The cascade only
breaks if you widen a *caller* before its callees (that was the failed A2.2 /
step-1 probe). Convention (model-ops CLAUDE.md rule 9):
- device-only fn → `device: &impl Device`
- device+stream fn → `fn f<D: Device>(device: &D, stream: &D::Stream, …)`

Gate per layer: `cargo build`/`clippy` (model-ops + forward, `hip`) + the
forward parity/synth suite on gfx906. Engine-level layers also gate on a live
pp2tp2 byte-identical greedy-decode md5 (gemma-4-26B-A4B + qwen3.6-27B; baseline
`805a6178…` / `cb529e9c…`).

### 3b — the de-atomized remainder (incremental, green per file)

Because `B` defaults to `HipBackend`, each user can be widened on its own and
still compiles (callers infer `B` from the concrete `CoreState` they hold).
Order by call-graph depth (callees first):
1. **Body-neutral composites** (`standard_attn`, `dense_ffn`, `moe_ffn`,
   `rmsnorm`, `embed`, `output_head`, `residual_add`, `standard_attn_mixed`) —
   no `Hip*` in the body; just add `<B: Backend>` + `CoreState<'_, B>`. Trivial.
2. **`ctx.rs` `ForwardCtx`** default methods that name `flambeau_ops::HipOps`
   (~ lines 227, 294) → `&impl Ops` (widening; callers coerce).
3. **The AR seam in the hooks** — `TopologyHooks`/`StageHooks` method sigs +
   the `gdn`/`gdn_mixed` `ArCallback` closures `|…, dev: &HipDevice, stm:
   &HipStream|` + `ArCallback` itself (engine.rs) are still `HipDevice`-typed.
   This is the one genuinely-coupled sub-step: the closures feed the
   `HipDevice`-typed `ArCallback`/`TopologyHooks`, so those must take the seam
   (`&B::Device`/`&B::Stream`) together. C1–C3 already moved the AR *bodies*
   behind `BarArRank`, so this is signature-threading, not logic.
4. **`engine.rs`** — the 4 `ForwardCtx` impl structs + `TpHooks`/`HybridHooks`
   + `ForwardEngine` gain `<B>`; `TpHooks`/`HybridHooks` swap
   `Arc<BarArCoordinator>` for a generic `FusedAllReduce` handle.
5. **`runtime/workers.rs`** — `HipOps::new(reg, stream)` → `B::ops(...)`,
   per-rank `CoreState::<HipBackend>::new`; **`runtime/mod.rs`** `Session`
   fields. These pin `B = HipBackend` at the construction boundary (the one
   place HIP is named, correctly — it's the HIP backend selection point).

Gate each: build/clippy + forward parity; gate steps 3–5 on the live pp2tp2
byte-identical md5 (they touch the AR call path).

Prereqs already landed: A2.1 loaders (`c8e7982`); AR seam C1 `DeviceAllReduce`
(`99e151c`), C2 `FusedAllReduce` (`c5b2621`), C3 fused-AR routed through it
(`76b5e55`, live-gated).

## Layer 3 — the atomic core (next session)

Not mechanical like 1–2: `CoreState` is the hub the whole engine borrows
through, so the struct + every user must take `<B: Backend>` **together** — the
crate does not compile until the layer is fully converted. Cannot be
green-incrementally committed; start it only with a full context budget.

Remaining HIP-named surface (post layers 1–2), ~130 refs across 9 files:
- `core/state.rs` — `CoreState<'a>` fields `device: &HipDevice`,
  `stream: &HipStream`, `reg: &OpsRegistry` → `B::Device` / `B::Stream` /
  `B::Registry`. **This is the hub.**
- `ctx.rs` — `ForwardCtx` trait surface.
- `engine.rs` — the 4 ctx impls (`SingleDevice`/`Tp`/`Pp`/`Hybrid ForwardCtx`),
  `TpHooks`/`HybridHooks` structs (swap `Arc<BarArCoordinator>` for a generic
  `FusedAllReduce` handle — C1–C3 made this a type swap, not a logic change),
  `ForwardEngine`.
- `core/hooks.rs` — `TopologyHooks`/`StageHooks` method sigs
  (`device: &HipDevice, stream: &HipStream` → the seam). C3 already routed the
  AR *bodies* through `BarArRank`; only the **signatures** remain HIP-typed.
- `core/composites/gdn.rs`, `gdn_mixed.rs` — the `ArCallback` closures
  `|buf, n, dev: &HipDevice, stm: &HipStream|` (tied to the hook sigs → move
  with the engine).
- `runtime/workers.rs` — constructs `CoreState` + the ctx impls per rank;
  `HipOps::new(reg, stream)` → `B::ops(reg, stream)`.
- `runtime/mod.rs` — `Session` device/stream/reg fields.
- `runtime/ar.rs` — the HIP AR impl (`BarArCoordinator`, `bar_ar_*`) stays
  `HipDevice`-typed (it IS the HIP backend); only the engine's generic callers
  change.

Suggested order within layer 3 (still one compile unit, but build it up):
1. `CoreState<'a, B: Backend>` + its `new` in `state.rs`.
2. Thread `B` through the 4 `ForwardCtx` impl structs + `engine.rs`.
3. Genericize `TopologyHooks`/`StageHooks` sigs + the composites' closures.
4. `workers.rs` construction (`B::ops`, per-rank `CoreState<B>`).
5. Build; the model forward fns (`<C: ForwardCtx>`) should need no change.
6. Gate: forward parity/synth + live pp2tp2 byte-identical md5.

After layer 3: forward names no `Hip*` type; A2.2/A2.3 composites fall out for
free; then A3 (models + server) and Track B (the CUDA backend) per
`doc/CUDA-PORT-PLAN.md`.

Revised remaining shape: **3a (hub, done) → step 2 (ctx ops, done) → [steps
1+3+4 coupled: composites + hooks + engine collectives] → step 5 (workers
construction boundary)**. The coupled middle is the real Layer-3 core; do it in
one focused pass with the pp2tp2 gate.

### gdn coupling is deeper than estimated (2026-06-12)

gdn/gdn_mixed are NOT a closure-only widening. Their bodies thread:
- **`flambeau_model_ops::BackendCtx { device, stream }`** — concrete
  `&HipDevice`/`&HipStream`; needs to become generic over the Device seam
  (`BackendCtx<'a, D: Device>` or `<D>`-param), a model-ops change.
- the delta_net **`forward_prefill_with_ar_hook` / `forward_decode_with_ar_hook`**
  drivers, whose AR-hook callback is `FnMut(DevicePtr, usize, &HipDevice,
  &HipStream) -> Result<()>` — must widen to `&D::Device`/`&D::Stream` (or take
  the seam) so the gdn closure `|…, dev: &B::Device, stm: &B::Stream|` matches.

So **gdn = (model-ops: `BackendCtx` + GDN forward-driver AR-hook sigs over the
Device seam) THEN gdn composites over `<B, H: TopologyHooks<B>>` + closures**.
The model-ops part is a layer-1-style widening (green per the coerce rule); do
it first, then the gdn composites, then the pp2tp2 gate.

Gate plan (when gdn lands): one run is enough — md5 the current
(post-`sub-B`) binary's greedy decode and confirm it still equals the C3
baseline `gemma-4-26B-A4B 805a6178…` / `qwen3.6-27B cb529e9c…` (3a/step2/sub-A/
sub-B are all type-only, so the whole Layer-3 chain should be byte-identical);
then md5 the post-gdn binary and confirm it matches too. `.probe/c3_gate.py`,
`LABEL=pre`/`post`, pp2tp2 `hip:0,2,1,3`.
